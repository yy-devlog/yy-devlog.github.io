# 実測ログの入力ガイド(手入力が基本)

Apple Watch と Fitbit Air の数字を、**手で** Google スプレッドシートに入力して、サイトのグラフに反映する手順です。
ヘルスケアからの自動入力(ショートカット)は、いまはお休みにしています(`docs/ios-shortcut-guide.md`)。
自動化は、SE 3 と Fitbit Air が揃ってから、もう一度考えます。

## 大切な約束

- **SE 3 が届くまでは、`Apple Watch SE3` の行を実測データとして入力しない**でください(いまのApple WatchはSeries 9のため)。
  仕組みの確認で入れた行は、確認できたら、シートから消します。
- シートの内容は、サイトに載って公開されます。家族の名前・場所など、個人が特定される内容は書かない。
- シートを「ウェブに公開」したURL(下の手順2)は、他人に配らない。ただし、内容はサイトで公開されるデータなので、合言葉ほどの秘密ではありません。

---

## パート1: 最初に一度だけ

### 手順1: スプレッドシートを作る
図入りの手順は、Claude が作った手順ページにあります。要点だけ書きます。

1. Googleスプレッドシートを新しく作る(名前は自由。例: 実測ログ)。
2. タブを2枚にして、名前を **「日次」** と **「ワークアウト」** にする(この名前のとおりに)。
3. それぞれのタブの A1 に、`data/templates/` の列名(1行目)を貼り付ける。
   - 「日次」← `daily_template.csv` の1行目
   - 「ワークアウト」← `workouts_template.csv` の1行目

### 手順2: シートを「ウェブに公開」して、URLを2つ控える
サイトが、シートの内容を読みに行くための設定です。

1. スプレッドシートの上のメニューから **ファイル → 共有 → ウェブに公開** を開く。
2. 「リンク」タブで、左の欄を「ドキュメント全体」から **「日次」**(タブ名)に変え、右の欄を「ウェブページ」から **「カンマ区切りの値(.csv)」** に変える。
3. **公開** を押し、表示されたURL(`https://docs.google.com/spreadsheets/d/e/……/pub?gid=……&output=csv` の形)をコピーして控える。
4. 同じ操作を、**「ワークアウト」タブ**でも行い、2つ目のURLを控える。

### 手順3: GitHub にURLを登録する
1. GitHub のリポジトリ `yy-devlog.github.io` の **Settings → Secrets and variables → Actions → Variables** タブを開く。
2. **New repository variable** で、次の2つを追加する。
   - Name: `SHEET_DAILY_CSV_URL` / Value: 「日次」のURL
   - Name: `SHEET_WORKOUTS_CSV_URL` / Value: 「ワークアウト」のURL

(片方だけの登録は、エラーで止まります。かならず両方を登録してください。)

### 手順4: 動作確認
1. リポジトリの **Actions** タブ → `Sync data, build and deploy` → **Run workflow** で、手動実行する。
2. 緑のチェックになれば成功です。赤い×なら、失敗したステップの文章を教えてください。

※ 実測データのページ(`compare.html`)は、Fitbit Air が届いて記録が始まるまで、公開されません。
公開前でも、Actions が成功すれば、シートの読み取りは動いています。

## パート2: 毎週の入力(日曜の夜まで)

サイトは、**毎週月曜の日本時間6:00頃**に、シートを読んで更新されます。日曜の夜までに、その週の分を入力しておきます。
入力が間に合わなかった週は、前の週のグラフが、そのまま表示されます。

### 「日次」タブ(1日に、2台で2行)

| 列 | 入れるもの |
|---|---|
| 日付 | `2026-10-05` のように(`2026/10/5` でも自動で直ります) |
| デバイス | `Apple Watch SE3` または `Fitbit Air`(この綴りのとおり) |
| 歩数 | 数字(必須) |
| 運動時間(分) | 機器ごとの表示のまま(必須) |
| アクティブ消費カロリー | 動いた分のカロリー。総消費と、どちらか分かる方(必須) |
| 総消費カロリー | 安静時を含む1日のカロリー |
| 睡眠時間(時間) | 2台とも着けて寝た夜だけ(必須) |
| 移動距離(km)、安静時心拍(bpm) | 任意 |
| 装着状況 | 「Air: 足首(日中)/手首(就寝)」など、数字に影響しそうなこと |
| 欠測 | 充電や付け忘れで、1日の大半が測れていない日に `○` |

**数字を見る場所(画面の名前は、iOS・アプリのバージョンで少し違います)**

| 項目 | Apple Watch(ヘルスケアアプリ) | Fitbit Air(Google Health アプリ) |
|---|---|---|
| 歩数 | 調べる → アクティビティ → 歩数 | 歩数 |
| 運動時間 | 調べる → アクティビティ → 運動 | アクティブな時間(名前は画面による) |
| 消費カロリー | アクティブエネルギー(と、安静時エネルギー) | 消費カロリー |
| 安静時心拍 | 調べる → 心臓 → 安静時心拍数 | 安静時心拍数 |
| 睡眠 | 調べる → 睡眠 | 睡眠 |

- **ヘルスケアの合計は、iPhoneとApple Watchの重なりを取り除いた値です。** Apple Watch だけの数字を見たいときは、歩数などの画面の下にある「データソース」(または「すべてのデータを表示」)から、Apple Watch の分を選びます。
- ヘルスケアには、Fitbit Air のデータも、Google Health との同期で入る可能性があります。**Air の数字は、混ざらないように、Google Health アプリの数字を使う**ことをおすすめします。

### 「ワークアウト」タブ(行った日のうちに、1回1行)
ランニング(トレッドミル)、インドアサイクリング、バスケットボールを、行った日のうちに書きます。数日たつと、どちらの数字か混ざりやすいためです。

| 列 | 入れるもの |
|---|---|
| 日付、種目 | 種目は、トレッドミル、インドアサイクリング、バスケットボールなど |
| 装着位置(Fitbit Air) | 足首 / 手首 |
| 条件メモ | トレッドミルの速度・傾斜、バイクの負荷の設定など |
| Apple Watch 時間・平均心拍・最大心拍・消費カロリー・距離 | 数字 |
| Fitbit Air 時間・平均心拍・最大心拍・消費カロリー・距離 | 数字 |
| 機器表示 距離・消費カロリー・出力・ケイデンス | トレッドミルやバイクの表示。ある種目だけ入力する |

### 月曜の朝の確認
- リポジトリの **Actions** タブで、`Sync data, build and deploy` が、緑のチェックになっているか。
- 赤い×なら、列名の間違い(貼り付けの崩れ)、URLの登録の間違いなどが考えられます。失敗したステップの文章を教えてください。
