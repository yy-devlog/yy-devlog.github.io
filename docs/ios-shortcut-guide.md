# iPhoneのショートカットで「日次」データを自動入力する手順(段階A: Apple Watch)

> **現在はお休み中です。** 入力は手入力が基本です(`docs/manual-entry-guide.md`)。SE 3 と Fitbit Air が揃ってから、もう一度考えます。
> 受け口(`scripts/gas/Code.gs`)は動作確認済みなので、そのまま使えます。
>
> **試してわかったこと(次に作るときの注意)**
> - 「URLの内容を取得」に、統計の「合計」をそのまま渡すと、「875件のヘルスケアを共有しようとしている」と止められる。
>   合計を「数字を丸める」→「テキスト」→「入力から数字を取得」の順に通して、ただの数字にすると、警告は出なくなった。
>   ただし、その後も `no numeric fields`(歩数が空)になり、原因は特定できていない。
> - `device` は `Apple Watch SE3` の綴りのまま(違うと `unknown device`)。
> - プロンプトでショートカットを作ると、`token` の欄が消えることがある。手で追加する。
> - 今のApple WatchはSeries 9。SE 3 に替えたあとで、ソースの設定などを見直す。

Apple Watch SE 3 の毎日の数字(歩数・運動時間・アクティブ消費カロリー・安静時心拍)を、
iPhoneの「ショートカット」アプリが読み取って、Googleスプレッドシートの「日次」タブに自動で書き込む仕組みです。
Fitbit Air の行は、Airが届いてから(段階B)試します。

## 全体の流れ

```
iPhoneのヘルスケア → ショートカット(数字を集める) → Google Apps Script(受け口) → スプレッドシート「日次」タブ → サイト(週1回の更新)
```

- **Google Apps Script**は、Googleが無料で提供している小さなプログラムの置き場所です。ここに「受け口」を作り、ショートカットが数字を送ります。
- 同じ「日付 + デバイス」を何回送っても、行は増えず、その行が上書きされます。手で入れた「装着状況」「欠測」の列は消えません。

## 安全のための約束

- 受け口には「合言葉(TOKEN)」を付けます。**合言葉と、受け口のURLは、他人に見せないでください。**
  GitHub(公開)や記事、SNS、私(Claude)との会話にも、貼らないでください(貼らなくても、私は手順の確認ができます)。
- 送るのは、公開して問題のない数字だけです(歩数、運動時間、消費カロリー、安静時心拍)。位置情報や、時刻ごとの細かいデータは送りません。
- もしURLや合言葉が漏れたかもしれないときは、手順7の方法で、すぐに無効にできます。

## 手順1: スプレッドシートを作る(まだの場合)

1. Googleスプレッドシートを新しく作る。ファイル名は自由(例: 実測ログ)。
2. タブを2枚にする。名前は、**「日次」**と**「ワークアウト」**(この名前のとおりにする)。
3. 「日次」タブの左上のセル(A1)を選び、`data/templates/daily_template.csv` の1行目の列名を貼り付ける
   (コピーして貼り付けると、列名が横に並んで入ります)。「ワークアウト」タブも、`workouts_template.csv` の1行目を同じように貼り付ける。
   うまくいかないときは、「ファイル > インポート > アップロード」で、CSVを読み込む方法もあります(挿入場所は「現在のシートを置換する」)。
   ※ 図入りの手順は、Claude が作った手順ページにあります。

## 手順2: 受け口(Apps Script)を作る

1. スプレッドシートの上のメニューから **拡張機能 > Apps Script** を開く。
2. 左の「コード.gs」(または Code.gs)の中身を、すべて消して、`scripts/gas/Code.gs` の内容を貼り付ける。保存(フロッピーのアイコン)。
3. 左の歯車「プロジェクトの設定」を開き、**タイムゾーン**が「(GMT+09:00) 東京」になっていることを確認する(違えば `Asia/Tokyo` に変える)。
4. 同じ画面の一番下の **スクリプト プロパティ** で「スクリプト プロパティを追加」を押す。
   - プロパティ: `TOKEN`
   - 値: 長いランダムな文字列(合言葉)。ターミナルで `openssl rand -hex 16` を実行すると作れます。
   - 保存する。この値は、**手順5でも使う**ので、パスワード管理アプリなどに控えておく。

## 手順3: 受け口を公開する(デプロイ)

1. 右上の **デプロイ > 新しいデプロイ** を押す。
2. 歯車から種類を **ウェブアプリ** にする。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
     (「全員」でも、合言葉(TOKEN)を知らない人の書き込みは、拒否されます。URLは他人に見せない)
3. 「デプロイ」を押す。初回は、Googleアカウントの承認画面が出ます。
   「このアプリは確認されていません」と出たら、**詳細 > (プロジェクト名)に移動(安全ではないページ)** から進めて、許可する。
4. 表示された **ウェブアプリのURL**(`https://script.google.com/macros/s/……/exec`)をコピーして、控えておく。

## 手順4: パソコンから試す(iPhoneを使う前の確認)

ターミナルで、次を実行します(`ウェブアプリのURL` と `合言葉` は、控えたものに置き換える)。

```
curl -L "ウェブアプリのURL" -H "Content-Type: application/json" -d '{"token":"合言葉","date":"2026-10-05","device":"Apple Watch SE3","steps":1234}'
```

- **`-X POST` は付けません。** Google は、書き込みのあとに別のアドレスへ転送して答えを返します。`-X POST` を付けると、その転送先にも POST してしまい、
  「現在、ファイルを開くことができません」というエラーページが返ります(書き込みは成功していることもあるので、シートを確認してください)。
- `{"ok":true,"action":"appended",...}` と返り、スプレッドシートの「日次」タブに、1行が追加されれば成功です。
- もう一度同じコマンドを実行すると、`"action":"updated"` になり、行が増えないことも確認してください。
- `unauthorized` と出たら、合言葉が違います。`sheet not found` なら、タブの名前が「日次」か確認してください。
- 確認できたら、試しに入れた行は、シートから手で消してください。

## 手順5: iPhoneのショートカットを作る

**画面の名前は、iOSのバージョンで少し違うことがあります。** 迷ったら、その画面のスクリーンショットを見せてください。

### 5-A. まず「昨日の歩数だけ」を送るショートカットを作る(1つずつ確認する)

ショートカットアプリで、右上の「+」から新しいショートカットを作り、名前を「日次をシートへ」とします。次のアクションを、上から順に追加します。

1. **日付**(「現在の日付」)を追加する。
2. **日付を調整**: 現在の日付から「1日」を**減算**する。
3. **日付を調整**: 上の結果の「**日の始まり**を取得」(名前は「開始日」)。
4. **日付を調整**: 開始日に「1日」を**加算**する(名前は「終了日」)。
5. **日付をフォーマット**: 開始日を、書式「**カスタム**」、書式文字列 `yyyy-MM-dd` で変換する(名前は「日付テキスト」)。
6. **ヘルスケアサンプルを検索**:
   - 種類: **歩数**
   - フィルタを追加: **開始日** が **開始日と終了日の間**(上で作った2つの日付を指定)
   - フィルタを追加: **ソース** が **あなたのApple Watch**(iPhone本体を選ぶと、数字が重なります)
   - **制限: オフ**(オンのままだと、一部の記録しか読まれません)
7. **統計を計算**: 上の結果の「**合計**」。これが「歩数」になる。
8. **URLの内容を取得**:
   - URL: 手順3の「ウェブアプリのURL」
   - 方法: **POST**
   - 本文をリクエスト: **JSON**
   - フィールドを追加(下の表のとおり)
9. **結果を表示**(または「通知を表示」): 手順8の結果を表示して、`"ok":true` を確認する。

| キー | 種類 | 値 |
|---|---|---|
| token | テキスト | 合言葉 |
| date | テキスト | 日付テキスト(5で作ったもの) |
| device | テキスト | `Apple Watch SE3`(この綴りのとおり) |
| steps | 数字 | 手順7の結果(歩数の合計) |

実行して、シートの「日次」タブに昨日の歩数が入れば、成功です。**iPhoneのヘルスケアアプリの、昨日の歩数と近いかも、確認してください。**
歩数が、ヘルスケアの表示の約2倍なら、ソースの絞り込みが効いていません(iPhoneの歩数も足されています)。

### 5-B. 項目を増やす

6〜7のセット(サンプルを検索 → 統計を計算)を、項目ごとにコピーして追加します。フィルタの設定(開始日・ソース)は、同じにします。

| 項目 | 種類(名前は近いもの) | 統計 | キー | 種類(JSON) |
|---|---|---|---|---|
| 運動時間 | 運動時間(Appleエクササイズ時間) | 合計 | activeMinutes | 数字 |
| アクティブ消費カロリー | アクティブエネルギー | 合計 | activeCalories | 数字 |
| 安静時心拍 | 安静時心拍数 | 平均 | restingHr | 数字 |

8のフィールドに、キーを追加します(値は、それぞれの統計の結果)。
**ヘルスケアアプリの「運動」「アクティブエネルギー」の数字と、近いかを確認してください。**

### 5-C. 過去7日分を送る(週に1回、手で実行する場合)

1〜9のアクション全体を、**繰り返す**(回数: 7)で囲みます。2の日付の調整で、「1日」の代わりに、
**繰り返しのインデックス**(1〜7)の日数を減算します。これで、昨日から7日前までの数字が、1回の実行で送られます。
同じ日は上書きされるので、毎日送っても、週に1回まとめて送っても、重複しません。

## 手順6: うまく動かないとき

| 症状 | 原因と対処 |
|---|---|
| 歩数が約2倍になる | ソースの絞り込みが効いていません。フィルタの「ソース」で、Apple Watch を選び直す。 |
| 数字が0、または空 | 「制限」がオンのまま、ロック中でヘルスケアが読めない、種類の選び間違いなどが考えられます。iPhoneのロックを解除して実行し直す。 |
| Google のエラーページ「現在、ファイルを開くことができません」 | `curl` に `-X POST` を付けている(外す)。または、URL の写し間違い、デプロイの「アクセスできるユーザー」が「全員」になっていない。ブラウザでURLを開いて、`{"ok":true,"message":"ready"}` と出るかで、URLとデプロイの問題かを切り分けられます。 |
| `unauthorized` | 合言葉(TOKEN)が、スクリプト プロパティと違う。 |
| `date must be YYYY-MM-DD` | 日付のフォーマットが違う。`yyyy-MM-dd` にする(`YYYY` の大文字は、年の数え方が違うので避ける)。 |
| `sheet not found` | タブの名前が「日次」になっていない。 |
| シートの日付が、日付のずれた行になる | Apps Scriptのタイムゾーンが、東京になっていない(手順2の3)。 |
| 時間を決めた自動実行が動かない | iPhoneがロック中は、ヘルスケアのデータを読めないことがあります。まずは手で実行する(ホーム画面に追加すると、1タップで実行できます)。 |

## 手順7: URLや合言葉が漏れたかもしれないとき

1. Apps Scriptの「プロジェクトの設定」で、`TOKEN` の値を、別のランダムな文字列に変える(これで、古い合言葉は使えなくなります)。
2. ショートカットの token も、新しい値に変える。
3. さらに念のため、「デプロイを管理」から、古いデプロイをアーカイブして、新しくデプロイし直す(URLが変わる)。

## 段階B(Fitbit Airが届いてから)

- Fitbit Air のデータが、ヘルスケアの中で「別のソース」として見えるか(Google Healthとの同期のおかげで、見える可能性があります)を、まず確かめます。
- 見えれば、同じショートカットの「ソース」だけを変えて、`device` を `Fitbit Air` にして送れます。
- 見えなければ、Google Health アプリの数字を見て、シートに手で入力します。
- 睡眠時間は、2台とも着けて寝た夜だけ比べます。Apple Watch の睡眠データを送る場合は、キー `sleepHours` を使います(取り出し方は、届いてから確認します)。
